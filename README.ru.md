Исследования с учетом версии прошивки и безопасные инструменты для
авторизованного владельцем доступа к модемам и маршрутизаторам турецких
интернет-провайдеров.

> [!IMPORTANT]
> Для первой цели — Türk Telekom ZTE H3600P с прошивкой
> `H3600P V9.0 TTN.10_260210` — сейчас **нет публично проверенного способа
> получения root- или super-admin-доступа**. Сообщается, что старые методы
> WAN/TR-069 исправлены в этой версии. Проект распознает точную прошивку и
> останавливается, а не применяет старый рецепт.

## Возможности

- Точный каталог по провайдеру, устройству, аппаратной ревизии и прошивке.
- Раздельные статусы для обычного Web-admin, привилегированного Web-admin,
  локальной оболочки, UID 0 и загрузчика.
- Проверка ровно одного частного IP-адреса без обнаружения устройств и
  сканирования сети.
- План без изменений и необязательная проверка явно указанных портов.
- Шаблон исследовательского отчета без секретных данных.
- Документация на пяти языках.

Проект не содержит списков паролей, перебора, утекших учетных данных,
сканирования Интернета, закрытых прошивок, сторонних VM-образов или
автоматического downgrade/cross-flash.

## Провайдеры

В каталог включены TurkNet, Turkcell Superonline, Türksat Kablonet, Türk
Telekom, Netspeed, Vodafone Net и Millenicom. Наличие провайдера в каталоге не
означает поддержку всех его устройств.

## Быстрый старт

Требуется стандартный CPython 3.11–3.15. Установка также включает валидатор JSON Schema:

CI нацелен на стандартный CPython 3.11–3.15 на Windows, Linux и macOS. Python
3.15 сейчас является кандидатом в релизы: локальные проверки совместимости
выполняются на 3.15.0rc2, а не на финальной версии. CI выбирает предварительную
версию 3.15 только до выхода финальной; перед заявлением о подтверждённой
поддержке финальной версии необходимо заново прогнать всю матрицу на финальной
версии. Free-threaded Python и PyPy не входят в эту матрицу. Совместимость
интерпретатора не доказывает совместимость модема/конфигурации/прошивки.

```shell
python -m venv .venv
python -m pip --python .venv install --require-hashes -r requirements-ci.lock
python -m pip --python .venv install -e . --no-deps --no-build-isolation
python -m pip --python .venv check
```

Активируйте окружение командой `. .venv/bin/activate` в Linux/macOS или
`.venv\Scripts\Activate.ps1` в PowerShell. Затем выполните:

```shell
cpe-atlas providers
cpe-atlas devices
cpe-atlas validate
cpe-atlas status --isp "turk-telekom" --model "ZTE H3600P" --hardware-revision "V9.0" --firmware "H3600P V9.0 TTN.10_260210"
```

Установка опубликованного wheel, обновление и откат описаны в
[руководстве по установке](docs/installation.md).

Проверка одного частного адреса без соединения:

```shell
cpe-atlas doctor --host 192.168.1.1
```

Проверку готовности для точной версии прошивки можно выполнить в режиме
только чтения:

```shell
cpe-atlas root-readiness --isp "turk-telekom" --model "H3600P" --hardware-revision "V9.0" --firmware "H3600P V9.0 TTN.10_260210" --firmware-input firmware.bin --expected-sha256 <приватно-сохраненный-sha256>
```

Команда хеширует и проверяет файл только как непрозрачный набор байтов; для
текущей записи TTN.10 ожидаемым результатом является `STOP`. Она не
подключается к устройству, не создает конфигурацию и ничего не прошивает.
`cpe-atlas firmware-inspect` выполняет такую же безопасную проверку хеша и
версии частного файла прошивки. `config-generate` — автономный инструмент, а
не root-эксплойт и не прошивальщик; созданные файлы и резервные копии должны
оставаться приватными.

**Предупреждение:** не импортируйте зашифрованные конфигурации, созданные
v0.4.0a1 или более ранними версиями: ключи вычислялись неверно. Храните
исходную резервную копию приватно. [Исправление v0.4.0a2](docs/config-cryptography.md)
не доказывает безопасность импорта или получение root на точной версии прошивки.
Для зашифрованного вывода также требуется `--acknowledge-legacy-crypto`.
Формат производителя использует устаревшее выведение SHA-256 и CBC без
аутентификации; это подтверждение не превращает его в современную безопасную
резервную копию. Даже с `--force` путь вывода должен отличаться от исходной
приватной копии.

Команда `apply` в этой версии намеренно работает по принципу fail-closed и не
изменяет устройство для заблокированного рецепта.

## Сбор свидетельств из Web-интерфейса

Используйте сборщик только на собственном H3600P или при явном разрешении на
его администрирование, через доверенную изолированную либо напрямую
подключённую локальную сеть:

```shell
cpe-atlas web-evidence --isp "turk-telekom" --model "H3600P" --hardware-revision "V9.0" --firmware "H3600P V9.0 TTN.10_260210" --host 192.168.1.1 --username admin --i-own-or-administer-this-device --acknowledge-local-http-authentication
```

Пароль запрашивается со скрытым вводом. Подтверждение HTTP обязательно:
механизм challenge/hash в прошивке не обеспечивает защищённый канал против
перехвата локальной HTTP-аутентификации или подбора слабого пароля офлайн.
Используйте сильный пароль, уникальный для этого устройства. Выполняется ровно
одна обычная попытка входа, без автоматических повторов. Неверный пароль всё
равно может увеличить счётчик блокировки учётной записи.

После входа выполняются только фиксированные ограниченные GET-запросы главной
страницы и состояния устройства. Представления `tr069`, `rsc`, управления
пользователями, `mirror` и `capture` запрашиваются только тогда, когда
аутентифицированная карта доступа объявляет те же идентификаторы. JSON содержит
структуры ответов, уровни доступа, разрешённые имена и наблюдения маркеров.
Пароли, cookies, значения параметров и исходные страницы не выводятся и не
сохраняются. Настройки не отправляются; запросы CWMP, оболочки, сброса,
перезагрузки, загрузки файлов и прошивки не выполняются. Эти наблюдения не
доказывают root-доступ или поддержку устройства.

## Анализ UART офлайн

Исследуйте уже имеющийся приватный журнал UART без публикации исходного текста:

```shell
cpe-atlas uart-evidence --isp "turk-telekom" --model "H3600P" --hardware-revision "V9.0" --firmware "H3600P V9.0 TTN.10_260210" --input h3600p-uart-private.log
```

Команда читает не более 8 MiB локального файла, не открывает последовательный
порт и ничего не отправляет устройству. Выводятся только ограниченные
разрешённые метаданные загрузки и наблюдения маркеров: без исходных строк,
пути файла, конфиденциальных идентификаторов или секретов. Если одновременно
наблюдаются ожидаемая прошивка и другая сборка, `firmware_identity_status`
равен `conflicting-builds-observed`. Повторения и различия только в регистре
одной сборки не считаются конфликтом. Даже `matched` означает лишь наблюдение
строки версии; приглашение оболочки или текст UID 0 не подтверждают root.
`root_access_verified` всегда остаётся `false`.

## Приватная идентификация и конфигурация

Чтобы серийный номер и MAC-адрес не попадали в историю оболочки и аргументы
процессов, сохраните ровно `{"serial":"...","mac":"..."}` в защищённом от
постороннего доступа JSON-файле UTF-8 и используйте `--identity-file`.
Чтение ограничено 1 KiB, содержимое не выводится. MAC должен быть записан
строчными буквами; этот параметр нельзя сочетать с `--serial` или `--mac`.
Пример создания зашифрованного исследовательского файла офлайн из приватной
резервной копии:

```shell
cpe-atlas config-generate --isp "turk-telekom" --model "H3600P" --hardware-revision "V9.0" --firmware "H3600P V9.0 TTN.10_260210" --input-config config.bin --identity-file device-identity.private.json --output h3600p-research.bin --encrypted --acknowledge-legacy-crypto --acknowledge-unverified-compatibility --i-own-or-administer-this-device
```

Пароль SSH и необходимая ключевая фраза устройства запрашиваются со скрытым
вводом. Для заблокированных, исследуемых или не проверенных в точности целей
обязателен `--acknowledge-unverified-compatibility`. Подтверждение не доказывает
принятие файла прошивкой, root-доступ, сохранность сервисов или возможность
восстановления. Без исходной копии минимальный шаблон не сохраняет настройки
Internet/VoIP/IPTV/VLAN/Wi-Fi/TR-069 провайдера. Незашифрованный вывод с учётными
данными требует явного `--allow-unencrypted`. Храните оригинальную копию, файл
идентификации и результат отдельно в приватном доверенном каталоге. Даже с
`--force` результат не может заменить исходную копию или файл идентификации.

Если скрытый ввод недоступен, команда завершается без перехода к видимому
вводу. В автоматизации `--ssh-password-stdin` и `--device-key-stdin` читают
приватный канал или защищённый файл. Если нужны оба значения, сначала передайте
пароль SSH, затем ключевую фразу устройства, по одному на строку LF/CRLF.
Пароль SSH должен содержать 8–128 печатных символов, фраза устройства — ровно
32 ASCII-символа. Слишком длинные значения отклоняются, а не обрезаются.
Эти параметры не отключают эхо терминала: не используйте их для интерактивного
ввода видимых секретов и никогда не указывайте секреты в аргументах команд.

## Аутентифицированная защита локальных файлов

Эти команды предназначены только для приватных файлов, с которыми вы имеете
право работать, и запрашивают ключевую фразу со скрытым вводом:

```shell
cpe-atlas private-protect --input config.bin --output config.bin.cpap --i-am-authorized-to-handle-this-private-file
cpe-atlas private-unprotect --input config.bin.cpap --output restored-config.bin --i-am-authorized-to-handle-this-private-file
```

Новые контейнеры используют формат версии 2, свежую соль, аутентификацию
AES-GCM и scrypt с `N=2^17`, `r=8`, `p=1`. `private-unprotect` также читает старые
контейнеры версии 1. Для миграции успешно расшифруйте контейнер версии 1 в
отдельный приватный файл, затем защитите его заново; новые записи всегда
используют версию 2. Неизвестные или чрезмерные параметры KDF отклоняются до
выведения ключа.

Этот формат **не предназначен для импорта в модем**. Он не удаляет секреты,
не доказывает совместимость прошивки и не делает резервную копию пригодной
для публикации. Храните контейнер и ключевую фразу отдельно; не добавляйте их
в репозиторий или отчёт об ошибке. Расшифрованные файлы и автоматически
отредактированные отчёты также остаются приватными: перед передачей проверяйте
их вручную. Фраза должна содержать 12–256 Unicode-символов без управляющих
символов C0/C1, разделителей строк/абзацев и суррогатов. Сохраните точный текст:
нормализация Unicode и удаление пробелов не выполняются.

При недоступном скрытом вводе команда останавливается. В автоматизации
`--passphrase-stdin` читает фразу защиты, а `--password-stdin` — пароль
Web-интерфейса. Используйте только приватный канал или защищённый файл:
эти параметры также не отключают эхо и не подходят для ввода секретов в
видимом терминале. Подробности приведены в
[криптографических примечаниях](docs/config-cryptography.md#authenticated-local-container),
[справочнике CLI](docs/cli-reference.md) и
[контракте JSON и кодов завершения](docs/cli-output-contract.md).

## Безопасность и разрешение

Используйте проект только для собственного оборудования либо при наличии
явного разрешения. Точно проверьте модель, аппаратную ревизию и прошивку,
сохраните сведения о настройках Internet, VoIP, IPTV, VLAN и Wi-Fi и заранее
проверьте восстановление. Не публикуйте резервные копии конфигурации, дампы
трафика, пароли, сертификаты, серийные номера, MAC-адреса и идентификаторы
абонента.

Для арендованного, выданного или принадлежащего провайдеру устройства требуется
его явное разрешение. Изменения могут повлиять на договор, гарантию,
техническую поддержку и работоспособность.
